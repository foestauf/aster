# Aster v0.7: Unwrapping Without `?` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `let P = e else { … };`, `if let`, the `never` type (for `panic`, `exit` and user functions) and diverging block arms in match expressions. Teach `parse.aster` and `check.aster` all of it, then dogfood it by rewriting `checker.aster` without sentinels, empty `None` arms or Option-to-bool wrappers.

**Architecture:** `let … else` and `if let` are new AST statements, and the checker turns each into an ordinary typed `match` statement: `[pattern → {}, _ → else]` for let-else, and `[pattern → then, _ → else]` for if-let. Lowering and C are untouched for them. Let-else binders keep their values after the match, because IR locals are function-wide slots. `never` is a new `Type` kind. It fits any expected type and makes a statement diverge. Lowering gets three small changes: calls of type `never` terminate with `unreachable`, nothing is emitted while no block is open, and dead blocks are pruned.

**Tech Stack:** TypeScript (Node 24, pnpm, vitest, oxlint), C11 runtime compiled with the system `cc`. The self-hosted programs are Aster.

**Spec:** `docs/superpowers/specs/2026-10-03-aster-v0.7-design.md` (read it first; this plan argues from it).

## Review Focus

1. **Let-else binders read after the match.** The binder slots must be filled in arm 0 and still hold the payload in
   the code after the statement, including inside a loop where the statement runs several times with different
   values. Pinned by a `buildAndRun` test in Task 4 and `unwrap/let_else_loop.aster` in Task 6.
2. **A `never` value in the middle of an expression.** `f(1, panic("x"))`, `panic("x") + 1` (an error) and
   `let x: int = if c { 1 } else { die("x") };` must lower without throwing `emitting into unreachable code` and produce
   C with no unused labels. Pinned in Task 3 by `buildAndRun` tests under `-Werror`.
3. **Shadowing and scope of binders.** An if-let binder must not leak past the `if`. A let-else binder must not be
   visible in its own else block. A let-else binder must conflict with an earlier `let` of the same name in the same
   scope. Pinned in Task 4 (checker tests) and `errors/let_else_scope.aster` in Task 6.
4. **Local-id order parity.** `check.aster`'s summary prints locals in id order: scrutinee temporaries don't exist, so
   the order is pattern binders, then the else/then block's locals. A mismatch shows up only in the summary diff.
   Pinned by `unwrap/` programs that declare locals in both the then-block and the else-block (Task 6).
5. **`else if let` chains and match-statement fallthrough with `never` arms.** `if let … else if let … else` must check
   and lower like nested matches, and a match *statement* whose arms all end in a user `never` call must count as
   diverging (no missing-return error). Pinned in Tasks 4 and 6.
