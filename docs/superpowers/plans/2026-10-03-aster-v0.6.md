# Aster v0.6: Imports Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an Aster program span several files with `import "path";` and one flat namespace, then delete `parse.aster`'s copied lexer by splitting `lex.aster` into a `lexer.aster` library.

**Architecture:**
- **Source map.** Every loaded file gets a global `base` offset in a `SourceMap`, and the lexer adds it to every span. The AST, checker, IR and backend keep plain `{ start, end }` spans and don't change. Diagnostics map offsets back to a file.
- **Loader.** A new loader (`driver/load.ts`) walks imports depth first through a `LoadHost`, which is `fs` in production and in-memory in tests. It dedups files by real path, merges every file's items into one `Program`, and reports `cannot import` along with the syntax errors.
- **Checker.** It gains only the root-file `main` rule.

**Tech Stack:** TypeScript (Node 24, pnpm, vitest, oxlint), C11 runtime compiled with the system `cc`. The self-hosted programs are Aster.

**Spec:** `docs/superpowers/specs/2026-10-03-aster-v0.6-design.md` (read it first; this plan argues from it).

## Global Constraints

- Generated C and the runtime must compile cleanly under `-std=c11 -Wall -Werror`.
- Existing golden programs and unit tests keep passing. Single-file behaviour, including every diagnostic position and
  message, must not change. The root file has `base` 0.
- Exact messages (copy verbatim): `cannot import '<path>': <reason>`, where `<path>` is the literal's value as written and
  `<reason>` is the OS reason (`No such file or directory`, `Is a directory`, …) or `invalid path` for a path containing
  `\0`; and `'main' must be declared in the root file`. Existing collision messages are reused unchanged.
- Golden short form: `L:C message` for the root file, and `path:L:C message` for other files, with `path` relative to the
  root file's directory and `/` separators.
- File layout: each file's `base` = the previous file's `base` + its `text.length` + 1, with the root at 0.
- Load order: the root, then a depth-first pre-order walk of imports in source order, skipping files already loaded (by
  real path).
- Conventional commits, each ending with the lines
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and
  `Claude-Session: https://claude.ai/code/session_01BEFkosKGhxvKwQnSx37gDJ`.
- Before each commit run `pnpm typecheck && pnpm lint && pnpm test`. All three must pass at every commit.
- Golden programs or fixtures that use `import` must not be added before Task 2 has taught `lex.aster` and `parse.aster`
  the syntax: the conformance tests run both over every `.aster` file and fixture.
- Golden format reminder (`tests/harness.ts`): `// expect-error: L:C message` lines in the leading comment block make a
  program compile-only. `// expect-stdout:` + `// line` comments give stdout. `expect-stderr`, `expect-exit`,
  `expect-args` and `expect-stdin` exist too. Compile-error goldens compare diagnostics in the order `compileToC`
  returns them, which is sorted by global offset.

## Review Focus

1. **Single-file positions unchanged.** Every existing golden and conformance span must be identical. This is pinned by
   the whole existing suite staying green at every commit, Task 3 especially.
2. **End-of-file offsets.** An error at EOF of an imported file (an unterminated string, a missing `}`) must map to that
   file, not the next. Pinned by a source-map unit test in Task 3 and an EOF syntax error in an imported file in Task 5.
3. **Dedup by real path.** `./lib.aster`, `lib.aster` and `sub/../lib.aster` are one file. Pinned by a loader unit test
   in Task 4.
4. **Relative paths from a subdirectory.** `sub/a.aster` importing `b.aster` resolves to `sub/b.aster`. Pinned by
   `modules/subdir.aster` in Task 5.
5. **The conformance suites compile from real paths** after the split, and lex/parse `lexer.aster` itself. Pinned by
   corpus assertions in Task 6.

### Task 3: Source map and global offsets

**Files:**
- Modify: `packages/asterc/src/diagnostics/source.ts`
- Modify: `packages/asterc/src/diagnostics/diagnostic.ts`
- Modify: `packages/asterc/src/lexer/lexer.ts` (add `source.base` to every span)
- Test: `packages/asterc/src/diagnostics/diagnostic.test.ts`, plus a new `packages/asterc/src/diagnostics/source.test.ts`
  if there is no source test yet

**Interfaces:**
- Produces:
  - `SourceFile` gains `base: number`. `makeSource(path, rawText, base = 0)` takes an optional third parameter.
  - `interface SourceMap { files: SourceFile[] }`, in load order.
  - `function sourceMapOf(files: SourceFile[]): SourceMap`, which validates the layout.
  - `function sourceAt(where: SourceFile | SourceMap, offset: number): SourceFile` returns the last file whose
    `base <= offset`. A lone `SourceFile` returns itself.
  - `function nextBase(file: SourceFile): number` returns `file.base + file.text.length + 1`.
  - `lineCol(where: SourceFile | SourceMap, offset)` subtracts the containing file's `base`.
  - `formatDiagnostic(where, d)` and `formatShort(where, d, root?: SourceFile)` accept `SourceFile | SourceMap`.
    - `formatDiagnostic` prints the containing file's `path`.
    - `formatShort` prints `L:C message` when the containing file is the map's first file (the root), and otherwise
      `relPath:L:C message`. `relPath` is that file's path relative to `dirname(root.path)`, converted to `/` separators.
    - Use `node:path`'s `relative` and `dirname`. `diagnostics/` may import `node:path`; check the package doesn't forbid
      Node imports there, and if it does, put the relative-path logic in the caller.

- [ ] **Step 1: Failing unit tests:**
  - Two files `a` (`"fn a() {}\n"`, base 0) and `b` (`"x"`, base `nextBase(a)`).
  - `sourceAt(map, a.text.length)` is `a`, since the EOF offset belongs to its own file. `sourceAt(map, b.base)` is `b`.
  - `lineCol(map, b.base)` is `{ line: 1, col: 1 }`.
  - `formatShort(map, { message: 'm', span: { start: b.base, end: b.base + 1 } })`, with a root path of
    `/r/main.aster` and b's path `/r/lib/b.aster`, gives `lib/b.aster:1:1 m`.
  - A root-file diagnostic gives `1:1 m`.
  - `lex(makeSource('b', 'fn', 100))` gives tokens whose spans start at 100.
- [ ] **Step 2: Run them and confirm they fail.**
- [ ] **Step 3: Implement.** Every existing caller compiles unchanged, because a single `SourceFile` is accepted where a
  map is.
- [ ] **Step 4: Run `pnpm typecheck && pnpm lint && pnpm test`.** All existing goldens must be byte-identical.
- [ ] **Step 5: Commit.** `feat(diagnostics): source map with global offsets`

### Task 4: Loader, pipeline and the root-file `main` rule

**Files:**
- Create: `packages/asterc/src/driver/load.ts`
- Create: `packages/asterc/src/driver/load.test.ts`
- Modify: `packages/asterc/src/driver/pipeline.ts`
- Modify: `packages/asterc/src/check/checker.ts` (the `main` rule)
- Modify: `packages/asterc/src/index.ts` (export the loader)
- Test: `packages/asterc/src/check/checker.test.ts`, `packages/asterc/src/driver/driver.test.ts`

**Interfaces:**
- Consumes: Task 3's `SourceMap`, `makeSource(path, text, base)`, `nextBase`, and Task 1's `Program.imports`.
- Produces:
  - `interface LoadHost { readFile(path: string): { ok: true; text: string } | { ok: false; reason: string }; realPath(path: string): string }`
    and `nodeHost: LoadHost`.
    - `readFile` returns `reason` as the OS message without the errno prefix: for `ENOENT`, `No such file or directory`.
      Map the codes the same way the runtime's `read_file` does. Look at `packages/asterc/runtime/aster_rt.c` and reuse
      `strerror`-style texts: `ENOENT` → `No such file or directory`, `EISDIR` → `Is a directory`, `EACCES` →
      `Permission denied`, otherwise the Node message.
    - A path containing `\0` gives `invalid path`. A directory must give `Is a directory`: Node's `readFileSync` on a
      directory throws `EISDIR`, so check it.
    - `realPath` falls back to `path.resolve` if `fs.realpathSync` throws.
  - `function loadProgram(root: SourceFile, host: LoadHost): { map: SourceMap; program: Program; rootEnd: number; diagnostics: Diagnostic[] }`.
    - `root` keeps base 0.
    - Imports are resolved with `path.resolve(dirname(importer.path), literal)`. The display path stored in each
      `SourceFile.path` is `path.join(dirname(importer.path), literal)`, unless the literal is absolute.
    - The walk is depth-first pre-order with a `Set` of real paths.
    - Each new file gets `base = nextBase(previous file in load order)`.
    - `program` concatenates `functions`, `structs`, `enums` and `imports` in load order.
    - `rootEnd = root.text.length`.
    - `diagnostics` holds every file's lexer and parser diagnostics, plus `cannot import` at the literal's `pathSpan`.
  - `runFrontend(root: SourceFile, host: LoadHost = nodeHost)` and `compileToC(root, host = nodeHost)` return their
    current results plus `map: SourceMap`. When loading reports diagnostics, the frontend stops before checking.
  - `check(program, options?: { rootEnd?: number })`. A `fn main` whose `nameSpan.start >= rootEnd` reports
    `'main' must be declared in the root file` at its name and is skipped, as if not declared. The missing-main check
    only considers root declarations.

- [ ] **Step 1: Failing loader tests with an in-memory host** (a `Map<string, string>` keyed by absolute path, with
  `realPath` normalising via `path.resolve`):
  - Load order: the root imports `a` and `b`, and `a` imports `c`. The files come out as root, a, c, b, with bases laid
    out by `nextBase`.
  - Dedup: `./lib.aster`, `lib.aster` and `sub/../lib.aster` load once.
  - Cycle: `a` imports the root. Self-import: the root imports itself. Both terminate, with each file loaded once.
  - Subdirectory: `sub/a.aster` imports `b.aster`, which loads `/r/sub/b.aster`.
  - Missing file: `cannot import 'nope.aster': No such file or directory`, spanning the literal.
  - A syntax error in an imported file is in `diagnostics` with a span inside that file's range.
  - In `checker.test.ts`, `main` declared past `rootEnd` reports the new message, and a root without `main` still
    reports `missing 'fn main(): int'`.
- [ ] **Step 2: Run them and confirm they fail.**
- [ ] **Step 3: Implement** `load.ts`, the pipeline changes and the `main` rule. In the pipeline, sort every diagnostic
  with `sortDiagnostics` (global offsets order them by load order, then position).
- [ ] **Step 4: Run `pnpm typecheck && pnpm lint && pnpm test`.**
- [ ] **Step 5: Commit.** `feat(driver): load imported files into one program`
