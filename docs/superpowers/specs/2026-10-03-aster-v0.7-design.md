# Aster v0.7: Unwrapping Without `?` (Design)

**Date:** 2026-10-03
**Status:** Approved in brainstorming
**Builds on:** [`2026-10-03-aster-v0.6-design.md`](2026-10-03-aster-v0.6-design.md) and
[`2026-10-03-aster-check-aster-design.md`](2026-10-03-aster-check-aster-design.md). Everything in v0–v0.6 still holds
unless this document changes it.

## 1. Purpose

v0.7 takes on item 1 of the v0.7 shortlist in [`docs/self-host/friction.md`](../../self-host/friction.md), entry 10:
unwrapping an `Option` in a function that can't use `?`. `checker.aster` uses `?` 0 times in 2,558 lines. Instead it
has 26 empty `Option::None => {}` arms, 4 find-or-bail sentinels (`oi`, `ri`, `si`, `name = ""`), 5 wrappers that only
turn an `Option` into a `bool` (`is_found` alone has 15 calls), and a `panic` written out twice because a match arm
couldn't leave early.

| Construct | Removes |
|-----------|---------|
| `let P = e else { … };` | the find-or-bail sentinels |
| `if let P = e { … } else …` | empty `None` arms and the Option-to-bool wrappers |
| the `never` type (`panic`, `exit`, and user `fn f(): never`) | arms that can't end a match expression |
| diverging block arms in match expressions | the duplicated `panic` and the report-then-sentinel dance |

Maps and sets (shortlist item 2) are the next milestone.

### Success criteria

v0.7 is done when:

1. The golden suite covers every feature in §3, including every new compile error.
2. `parse.aster` and `check.aster` handle all v0.7 syntax and rules. `tests/parse_aster.test.ts` and
   `tests/check_aster.test.ts` pass over the whole corpus, including the new golden programs and fixtures, and the
   diagnostic audit in `check_aster.test.ts` lists every new message with a file that triggers it.
3. `checker.aster` is rewritten onto the new forms (§5.3):
   - 0 find-or-bail sentinels
   - 0 empty `Option::None => {}` arms
   - `is_found` deleted, and the other four Option-to-bool wrappers deleted wherever every call site becomes an
     `if let` or `let … else`
   - the duplicated `panic` in `check_generic_variant_expr` written once
   `parser.aster` and `loader.aster` take the same rewrites wherever they apply.
4. `docs/spec/language.md`, `README.md` and `docs/self-host/friction.md` describe v0.7. The friction log marks entry 10
   resolved, with before and after counts (sentinels, empty `None` arms, wrappers and their calls, and lines).

### Non-goals for v0.7

`while let`, `if let … && cond` chains, `var` in pattern lets, irrefutable destructuring `let`, blocks as if-expression
branches, `return`/`break`/`continue` as expressions, `never` in any position other than a return type, generic
functions, and maps.

## 2. Semantics decisions (summary)

- **`let P = e else { … };`** binds the pattern's names in the enclosing scope, or runs the else block, which must
  diverge.
- **`if let P = e { … }`** runs the then-block with the pattern's names bound when `e` matches. It takes an optional
  `else`, which can chain into `else if` or `else if let`.
- **Patterns** are the ones a `match` arm accepts, except `_`. An irrefutable pattern is an error.
- **`never`** is a built-in type name, valid only as a function return type. `panic` and `exit` return `never`. A user
  function declared `never` must diverge on every path and can't contain `return`. A `never` expression fits any
  expected type.
- **A match-expression arm may be a block** that must diverge. Arms of type `never` are ignored when the arms' types are
  unified.
- **No new runtime behaviour.** `let … else` and `if let` check to an ordinary typed `match` statement, so lowering and
  C emission for them are unchanged.

## 3. Language changes

### 3.1 Lexical

Nothing. `let`, `if` and `else` are already keywords. `never` is a predeclared type name like `void`, not a keyword.

### 3.2 Grammar

```
letStmt     = "let" IDENT ":" type "=" expr ";"
            | "var" IDENT ":" type "=" expr ";"
            | "let" pattern "=" expr "else" block ";" ;
ifStmt      = "if" ( expr | "let" pattern "=" expr ) block [ "else" ( ifStmt | block ) ] ;
matchExprArm = pattern "=>" ( expr | block ) ;
```

- **Telling the two `let` forms apart.** After `let`, an identifier followed by `::`, or a literal token (an int, a
  `-` before an int, a char, a string, `true` or `false`), starts a pattern. Anything else is the existing typed
  form. `let _ = …` is `expected identifier, found '_'`, as it is today.
- After the pattern, `=` and then the scrutinee expression. The scrutinee is parsed with struct literals disabled,
  exactly like an `if` condition. `else` is required (`expected 'else', found …`), then a block, then `;`.
- `if let`: the scrutinee is parsed with struct literals disabled, as an `if` condition is.
- A match-expression arm whose body starts with `{` is a block arm. As in match statements, the `,` after a block arm
  is optional. An expression arm still needs its `,` unless it is the last arm. Match-*statement* arms already accept blocks and
  don't change.
- If-expression branches stay `{ expr }`. A `{ stmts }` branch is not part of v0.7, because `{` can't tell a block from
  an expression branch without backtracking. A branch can still diverge through a `never` call.

### 3.3 Patterns in `let … else` and `if let`

- Any pattern a `match` arm accepts, except `_`: a variant pattern with binders, an int, char, string or bool literal,
  or an or-pattern. The same rules apply as in a match arm: unknown enums or variants, payload arity, binders in an
  or-pattern, the scrutinee category (`cannot match on '…' values`), and a pattern whose type doesn't fit the
  scrutinee.
- Binder types come from the scrutinee's payload types. No type annotation is written.
- **Irrefutable patterns are an error**, `pattern always matches`, at the pattern's span. A pattern is irrefutable when
  it covers every value of the scrutinee's type. Examples are `Wrapper::W(x)` on a single-variant enum, and
  `true | false`. Int and string scrutinees are never irrefutable. When the scrutinee or the pattern has an error, this
  isn't reported.

### 3.4 `let … else`

```aster
let Option::Some(si) = find_struct(ctx.env, name.name) else {
    report(ctx.env, "unknown struct '" + name.name + "'", name.start, name.end);
    return Type::Error;
};
```

- Order: the scrutinee is checked, then the pattern, then the else block. The binders are allocated when the pattern
  is checked (this fixes their local ids, which `check.aster`'s summary prints), and they enter scope only after the
  else block. The else block can't see them, and they shadow and conflict like other `let`s in the enclosing scope
  (`'x' is already declared in this scope`).
- The else block must diverge, in the sense the missing-return analysis already uses (`return`, `break`, `continue`,
  an infinite `while`, a diverging `if`/`match`, or a statement whose expression has type `never`). Otherwise the
  error is `'else' block of 'let' must diverge`, at the `else` keyword.
- Binders are immutable, like match binders.
- The `let … else` statement itself never diverges. It falls through when the pattern matches.

### 3.5 `if let`

```aster
if let Option::Some(local) = find_local(ctx, name.name) {
    return local.ty;
} else if let Option::Some(si) = find_struct(ctx.env, name.name) {
    …
}
```

- Order: the scrutinee is checked, then the pattern, then the then-block, then the else branch. Binders are scoped to
  the then-block only.
- An `if let` diverges when it has an else branch and both branches diverge, as `if` does.
- The `else` of a plain `if` can chain into an `if let` and vice versa.

### 3.6 The `never` type

- `never` is a built-in type name (`'never' is a built-in type and cannot be redefined`, as for `void`).
- It is valid only as a function's declared return type. Anywhere else (a variable, parameter, field, payload, array
  element or type argument) the error is `'never' is only allowed as a return type`, at the type's span. That replaces
  the more general errors that would otherwise apply there.
- `panic(msg)` and `exit(code)` now return `never`. That's a change from `void` with no effect on valid programs.
- **Compatibility.** An expression of type `never` fits any expected type: `expectType` accepts it everywhere a type
  is expected (a `let` initialiser, an assignment, an argument, a `return` value, a struct field, a payload, an array
  element, `push`'s value). `let x: int = panic("unreachable");` type-checks. Wherever the rules ask for a specific
  type without an expected type (an operator operand, a condition, `print`'s argument, `len`'s argument, a `match`
  scrutinee), `never` is reported like any other wrong type. `never` equals only `never`.
- **Divergence.** An expression statement or a `let` initialiser whose type is `never` makes that statement diverge.
  The existing special case for `panic` and `exit` calls is subsumed.
- **User `never` functions.**
  - `fn die(msg: string): never { eprint(msg); exit(1); }`
  - Its body must diverge on every path. Otherwise the error is `function 'die' returns 'never' but can reach its end`
    at the function name. This replaces the missing-return error for `never` functions.
  - Every `return` in it is an error, `cannot return from a function that returns 'never'`, at the `return`. The value,
    if any, is still checked, against no expected type.
  - `main` can't return `never`. The existing `'main' must have signature …` error covers it.
- **Unification.** In an if expression or a match expression, branches or arms of type `never` don't take part in the
  "same type" rule. The expression's type is the common type of the rest, or `never` if every branch or arm is
  `never`. The existing `if expression cannot have type void` / `match expression cannot have type void` rules apply
  to that type.

### 3.7 Diverging match-expression arms

```aster
let ty: Type = match find_struct(env, name) {
    Option::Some(i) => env.structs[i].ty,
    Option::None => {
        report(env, "unknown struct '" + name + "'", start, end);
        return Type::Error;
    },
};
```

- A block arm is checked as a block in the arm's scope (binders visible). It must diverge, or the error is
  `match arm block must diverge`, at the arm's pattern span. Its type is `never`.
- An expression arm may also be a `never` expression (`Option::None => panic("internal: …")`).

### 3.8 Example

```aster
enum Shape { Circle(int), Square(int), Dot }

fn die(msg: string): never {
    eprint(msg);
    exit(1);
}

fn side(s: Shape): Option[int] {
    return match s {
        Shape::Square(n) => Option::Some(n),
        _ => Option::None,
    };
}

fn area(s: Shape): int {
    let Option::Some(n) = side(s) else {
        return -1;
    };
    return n * n;
}

fn radius(s: Shape): int {
    return match s {
        Shape::Circle(r) => r,
        Shape::Square(_) => die("not a circle"),
        Shape::Dot => {
            print("dot");
            return 0;
        },
    };
}

fn main(): int {
    print(area(Shape::Square(3)));   // 9
    print(area(Shape::Dot));         // -1
    if let Shape::Circle(r) = Shape::Circle(4) {
        print(r);                     // 4
    }
    let code: int = 2;
    let 2 | 3 = code else {
        panic("bad code");
    };
    print(radius(Shape::Dot));       // dot, then 0
    return 0;
}
```

## 4. Compiler changes

### 4.1 AST and parser

- `Stmt` gains `{ kind: 'letElse'; pattern: Pattern; init: Expr; elseKeywordSpan: Span; else: Block; span: Span }`.
- `Stmt` gains `{ kind: 'ifLet'; pattern: Pattern; scrutinee: Expr; then: Block; else: Block | IfStmt | IfLetStmt | null;
  span: Span }`, and `IfStmt.else` may also be an `IfLetStmt`.
- `MatchExprArm.body` becomes `Expr | Block`.
- `sexpr` renders `letElse` as `(let-else P e block)`, `ifLet` as `(if-let P e then else)`, and a block arm as it renders
  blocks elsewhere.
- The `let` decision in §3.2 needs one token of lookahead past `let` (two for `IDENT ::`).

### 4.2 Types

`Type` gains `{ kind: 'never' }` with a `NEVER` constant. `typeToString` writes `never`. `typeEquals` needs no change.
`IrType` excludes `never` as it excludes `error`, because no IR local ever has that type. A `never` function's IR return
type is `void`.

### 4.3 Checker

- `never` joins the type-name table. `resolveType` gains a flag for return-type position. In any other position `never`
  is reported as in §3.6 and becomes the error type.
- `BUILTIN_SIGNATURES.panic` and `.exit` return `NEVER`.
- `expectType` accepts an actual type of `never`.
- Statement divergence: `expr` and `let` statements diverge when their expression's type is `never`.
- **`let … else`** checks to a typed `match` statement with two arms: the pattern with an empty body, then `wildcard`
  with the else block. Binder locals are created when the pattern is checked and declared into the enclosing scope
  after the else block. Because IR locals are function-wide slots, the binders keep the values the first arm assigned
  after the match.
- **`if let`** checks to a typed `match` statement with the pattern arm (the then-block) and a `wildcard` arm holding
  the else branch, or an empty block when there's none.
- Both reuse `checkMatch`'s pattern machinery (resolution, binder declaration, the `missingValues` coverage that
  decides irrefutability). The synthetic `wildcard` arm is never reported as unreachable, because the irrefutable
  case is reported first, as `pattern always matches`.
- **Match expressions**: a block arm is checked with `checkBlock` in the arm scope, must diverge, and contributes the
  type `never`. A typed match expression's arm body becomes `TExpr | TBlock`.
- **`never` functions**: `ctx.returnType` is `never`, `return` reports §3.6's error, and the end-of-body check is
  §3.6's.
- New diagnostics: `pattern always matches`, `'else' block of 'let' must diverge`, `match arm block must diverge`,
  `'never' is only allowed as a return type`, `function '<f>' returns 'never' but can reach its end`,
  `cannot return from a function that returns 'never'`, and `'never' is a built-in type and cannot be redefined` (an
  existing message with a new name).

### 4.4 IR and lowering

No new instructions or types. Lowering already models an unreachable position (no open block), which it enters after
`panic`, `exit`, `return`, `break` and `continue`. v0.7 builds on that:
- **Calls of type `never`** (`panic`, `exit` and user `never` functions) are emitted with no destination and followed by
  `unreachable`, as `panic` and `exit` are today. That now also covers user calls.
- **Placeholders.** When an expression is lowered with no open block, it emits nothing and yields a placeholder operand
  (the int `0`). `emit` discards instructions while no block is open, where today it throws. That makes
  `f(panic("x"))`, `panic("x") + 1` and `let x: int = panic("x");` lower without special cases.
- **Dead blocks.** Lowering can still open blocks with no predecessors, for example the right side of
  `panic("x") && c`. At the end of `lowerFunction`, blocks that can't be reached from the entry block are removed, so
  neither the placeholders nor unused labels reach C.
- **Block arms** of a match expression lower their statements and don't copy into the result local, since the block
  has already ended its control path.
- A `never` function's IR return type is `void`.

### 4.5 C backend

No change: a `never` function arrives as a `void` function with no unreachable blocks.

### 4.6 Unchanged

The lexer, the runtime, the driver, the loader and the CLI.

## 5. Self-hosted tools

### 5.1 Tree format (`parse.aster`)

| Node | Line | Children |
|------|------|----------|
| pattern let | `let-else S E` | the pattern, the scrutinee, then the else block |
| if let | `if-let S E` | the pattern, the scrutinee, the then block, then the else branch (`-`, an `if`, an `if-let` or a block) |
| match-expression block arm | `arm` | the pattern, then a `block` row (as match-statement arms already print) |

`S E` is the statement span, from `let` or `if` through the final `;` or `}`. The TS conformance printer in
`tests/parse_aster.test.ts` learns the same rows.

### 5.2 Checker (`check.aster`)

`checker.aster` implements §3 and §4.3 with the same diagnostics and the same local-id order (scrutinee, then pattern
binders, then the else or then block). The summary format is unchanged. `never` prints as `never` in function
signatures, and pattern-let binders print as `let` locals.

### 5.3 Dogfood rewrites

After parity is green:
- `checker.aster`: every find-or-bail sentinel becomes a `let … else`, every empty `None` arm becomes an `if let`,
  `is_found` and the other Option-to-bool wrappers go wherever their callers become `if let`/`let … else`, and the
  duplicated `panic` becomes a diverging arm.
- `parser.aster` and `loader.aster`: the same rewrites wherever they fit.
- The drivers (`lex.aster`, `parse.aster`, `check.aster`) may use a `never` helper for their usage and read-error
  exits if that removes duplication.

Each rewrite keeps every suite green. Afterwards the friction log records the before and after counts.

## 6. Testing

### 6.1 Golden programs

A new `unwrap/` folder:
- `let … else` on `Option`, `Result`, a user enum with a multi-binder payload, an int literal, an or-pattern, a char
  and a string. The else block diverges by `return`, `break`, `continue` (inside a loop), `panic`, `exit` and a user
  `never` call, and the expected output proves which path ran.
- `if let` with and without `else`, `else if`/`else if let` chains, shadowing a name inside the then-block, and an
  `if let` whose branches both diverge, ending a function without a trailing `return`.
- `never`: `let x: int = panic(…)` reached only on a failing path, a user `never` helper used in a value position, as
  a match-expression arm and as an if-expression branch, and a function whose last statement is a `never` call (so
  there's no missing-return error).
- block arms in match expressions that `return`, `break` and `continue`, plus a match expression whose arms are all
  `never`.

Additions to `errors/`:
- parse: `let Option::Some(x) = e;` (missing `else`), `let 1 = x else { return 0; }` without the `;`, `let _ = …`,
  and a block arm with a missing `}`.
- `pattern always matches` (single-variant enum, `true | false`) for both `let … else` and `if let`.
- `'else' block of 'let' must diverge` and `match arm block must diverge`.
- a let-else binder used inside its own else block (`unknown name`), an if-let binder used after the `if`, and a
  let-else binder that conflicts with an earlier `let` in the same scope.
- `never` as a variable, parameter, field, payload, array element and type argument type, and redefining `never`.
- a `never` function that can reach its end, `return;` and `return 1;` inside one, and `fn main(): never`.
- `never` where no expected type applies: `panic("x") + 1` and `print(panic("x"))`.

### 6.2 Self-hosted fixtures

`fixtures/parse_unwrap.txt` (every new form and its parse errors) and `fixtures/check_unwrap.txt` (any new diagnostic
the `errors/` programs don't reach). The existing fixture globs pick them up. The diagnostic audit in
`tests/check_aster.test.ts` gains a row for each new message.

### 6.3 Unit tests

Following the existing per-module pattern: the parser's `let` disambiguation and the new AST nodes, the checker's
desugaring into `match` and the `never` rules, the IR for a `never` call (an `unreachable` terminator), placeholders, and the
removal of blocks unreachable from the entry block.

### 6.4 Workflow

TDD per feature, golden tests first. Implementation order: AST and parser, then the checker (`never`, then `let …
else` and `if let`, then block arms), then lowering and C, then the self-hosted work (`parser.aster` parity,
`checker.aster` parity, then the dogfood rewrites), then the docs. Each step commits with its tests.

## 7. Looking ahead (informing, not in scope)

- **Maps and sets** (shortlist item 2) are the next milestone.
- **`while let`** would fit the same desugaring, but the corpus has no loop shaped like that yet.
- **Generic functions** would make an `is_some[T]` possible. After v0.7 the wrappers it would replace should be gone.
