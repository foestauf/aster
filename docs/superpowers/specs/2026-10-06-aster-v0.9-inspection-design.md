# Aster v0.9: Compiler Inspection for Humans and Agents (Design)

**Date:** 2026-10-06
**Status:** Approved in brainstorming
**Issue:** #53
**Baseline:** `cc7fcf1` (v0.8b, PR #52).
**Delivery:** v0.9a (structured checking) and v0.9b (declarations and types) as two PRs, v0.9b after v0.9a.

## 1. Purpose

A human or a coding agent should be able to ask the compiler what is wrong with a program, and what a declaration
means, without scraping human diagnostics or guessing from source. v0.9 adds two one-shot CLI capabilities that share
one versioned JSON contract:

- **v0.9a:** `aster check <entry> --format=json`: every failure, coded, with exact file-local locations.
- **v0.9b:** `aster inspect <entry>`: the same diagnostics plus, when the program checks, every named declaration in
  the entry point's import closure with its kind, location, resolved type and signature.

### Non-goals

LSP or any RPC/daemon transport, persistent sessions, incremental compilation, indexing beyond one entry point's
closure, references/rename, expression type-at-position, a formatter, freezing the AST or IR as a public API,
changes to human diagnostics, GC or backend changes.

## 2. Commands

```
aster check <file.aster> [--format=human|json]
aster inspect <file.aster>
```

- `--format=human` is the default; `aster check` without `--format` is byte-for-byte unchanged.
- `--format` is valid only with `check`. Any other value, or `--format` with another command, is a usage error.
- `inspect` emits JSON only and takes no options.
- The usage text gains both forms (one CLI golden changes, deliberately).

Usage-error reasons follow `parse_cli`'s existing style: `unknown format 'xml'`, `'--format' is only valid with
'check'`.

## 3. The response

One response per handled run: a single line of compact JSON followed by `\n` on stdout; stderr is empty. Keys
appear in the order shown; optional keys are omitted rather than `null` unless this document says `null`.

```json
{"schema":"aster/1","command":"check","ok":false,
 "files":[{"id":0,"path":"main.aster","bom":false},{"id":1,"path":"./lib.aster","bom":false}],
 "diagnostics":[
   {"code":"type.mismatch","severity":"error","message":"type mismatch: expected int, found string",
    "primary":{"file":1,"path":"./lib.aster","range":{"start":120,"end":125,"start_line":7,"start_col_utf16":5,"end_line":7,"end_col_utf16":10}},
    "related":[]}]}
```

`inspect` adds a final `semantics` key (§6).

| Key | Meaning |
|---|---|
| `schema` | Always `"aster/1"` for this version. |
| `command` | `"check"` or `"inspect"`. |
| `ok` | `true` exactly when `diagnostics` is empty. |
| `files` | Every loaded file, in load order. `id` is the load index (root = 0). `path` is spelled exactly as human diagnostics spell it (the root as given; an import as `dirname(importer) + "/" + literal`). `bom` says whether a UTF-8 byte order mark was stripped. A file that failed to load is not listed. |
| `diagnostics` | In human order (§3.3). |

### 3.1 Diagnostics

`{"code", "severity", "message", "primary", "related"}`.

- `code`: a stable dotted name (§4). The contract.
- `severity`: always `"error"` in v0.9 (the compiler has no warnings). Consumers must accept other values later.
- `message`: the human message, verbatim. **Not** part of the contract.
- `primary`: a location (§3.2).
- `related`: a list of `{"role": ..., <location fields>}`. The only role in v0.9 is `"import-target"` (§5).

### 3.2 Locations

`{"file", "path", "range"}`, plus `"path_exact": false` when the path is lossy (below).

- `file`: a `files` id, or `null` for a file that never loaded (a missing root, a failed import's target, a
  malformed file).
- `path`: always present.
- `range`: `null` when no source position exists (an unreadable file); otherwise
  `{"start", "end", "start_line", "start_col_utf16", "end_line", "end_col_utf16"}`.

Range rules:

- `start`/`end` are **half-open, zero-based byte offsets into the file's bytes as stored on disk**, a leading BOM
  included. They are authoritative; `start <= end`. Zero-width ranges (`start == end`) are legal, including at EOF.
- The loader's concatenated global offsets are never exposed.
- `end` is clamped to the end of the file, as the human formatter clamps it.
- Lines are 1-based. Only `\n` ends a line; a `\r` before it is an ordinary character of the line.
- Columns are 1-based and count **UTF-16 code units** from the start of the line, exactly as the human
  `file:line:col` column does: one per UTF-8 lead byte, two for a 4-byte (astral) sequence. Tabs count as one. The BOM
  is not counted (column 1 of line 1 is the first byte after it).
- `end_line`/`end_col_utf16` describe `end` the same way (the position just past the range).
- A range into a malformed UTF-8 file (§5) is `[B, B+1)` at the first ill-formed byte; its line/column are computed
  over the bytes before `B`, which are well-formed.

### 3.3 Ordering and deduplication

Exactly the human rule (`sort_diags` in `report.aster`): stable by global start offset (load order, then position),
dropping a diagnostic whose start and message equal an earlier one's. Human and JSON output therefore always report
the same diagnostics in the same order. Diagnostics with no range occur only alone (§5).

### 3.4 Serialisation

- Compact: no whitespace between tokens. Integers in decimal. Booleans `true`/`false`.
- Strings escape `"` as `\"`, `\` as `\\`, LF/CR/TAB as `\n`/`\r`/`\t`, other bytes below 0x20 as `\u00XX`
  (lowercase hex), and `0x7f` as `\u007f`. Everything else, including non-ASCII, is written as raw UTF-8.
- Source text is well-formed UTF-8 by the time it reaches any message. A **path** comes from argv or an import literal
  and may not be: each ill-formed sequence (Unicode Table 3-7, maximal-subpart rule) is written as U+FFFD, and every
  location carrying that path, and its `files` entry, gains `"path_exact": false`.
- Output is a function of the source snapshot, entry path and schema only: no timestamps, absolute paths, addresses
  or environment.

### 3.5 Compatibility policy (`aster/1`)

- May change within `aster/1`: new keys anywhere (consumers must ignore unknown keys), new codes, new declaration
  kinds and type kinds, new `related` roles, new `semantics.reason` values, message text.
- Never changes within `aster/1`: an existing key's type or meaning, an existing code's meaning, range units.
  Any such change is `aster/2`.
- There is no request version: requests are argv. Any unsupported `--format` is a usage error (§5).
- File and declaration ids are deterministic for the same source snapshot, entry path and schema. Nothing is stable
  across edits.

## 4. Diagnostic codes

Codes are assigned **at the producer**: `Diag` and `LexError` gain a `code` field, and every call site passes a
literal code. No code is derived from message text. A code names one message template; sites that produce the same
template share its code. `docs/inspect/README.md` holds the catalogue table and is authoritative;
`tests/diag_codes.test.ts` asserts that the set of code literals at producer sites equals that table.

The v0.9a catalogue (an implementation that finds a template not listed here adds a code in the same style, records it
in the README and calls it out in the PR):

| Phase | Codes (template) |
|---|---|
| `io` | `io.root-unreadable` (cannot read the root file) |
| `source` | `source.invalid-utf8` (root file is not well-formed UTF-8) |
| `lex` | `lex.invalid-escape`, `lex.unterminated-string`, `lex.unterminated-char`, `lex.empty-char`, `lex.invalid-char` (character literal is not a single character), `lex.unexpected-character` |
| `syntax` | `syntax.expected` (`expected X, found Y`, including expected expression/pattern/item), `syntax.chained-comparison`, `syntax.if-without-else`, `syntax.int-out-of-range` |
| `import` | `import.invalid-path`, `import.unreadable`, `import.invalid-utf8` |
| `decl` | `decl.builtin-type-redefined`, `decl.builtin-fn-redefined`, `decl.duplicate` (duplicate struct/enum/function), `decl.kind-conflict` (already declared as …), `decl.duplicate-field`, `decl.duplicate-variant`, `decl.void-field`, `decl.void-payload`, `decl.void-param`, `decl.void-variable` |
| `generic` | `generic.duplicate-param`, `generic.param-conflict`, `generic.unused-param`, `generic.infinite-expansion`, `generic.cannot-infer` |
| `typeref` | `typeref.unknown`, `typeref.not-generic`, `typeref.arity`, `typeref.void-argument`, `typeref.void-element`, `typeref.never-position`, `typeref.map-key`, `typeref.map-void-value` |
| `main` | `main.not-in-root`, `main.bad-signature`, `main.missing` |
| `flow` | `flow.never-reaches-end`, `flow.missing-return`, `flow.return-in-never`, `flow.missing-return-value`, `flow.void-return-value`, `flow.outside-loop`, `flow.let-else-not-diverging`, `flow.arm-not-diverging` |
| `name` | `name.duplicate-local`, `name.undefined`, `name.function-as-value`, `name.unknown-enum`, `name.not-an-enum`, `name.unknown-variant`, `name.unknown-struct`, `name.unknown-field` |
| `type` | `type.mismatch`, `type.condition`, `type.not-iterable`, `type.range-bound`, `type.unary-operand`, `type.binary-operands`, `type.not-comparable`, `type.if-branches`, `type.void-if`, `type.index`, `type.not-indexable`, `type.missing-field`, `type.duplicate-field-init`, `type.empty-array`, `type.void-element`, `type.empty-map`, `type.empty-map-mismatch`, `type.variant-arity` |
| `try` | `try.operand`, `try.return-type`, `try.error-type` |
| `match` | `match.scrutinee`, `match.unreachable-arm`, `match.irrefutable`, `match.non-exhaustive`, `match.arm-types`, `match.void` |
| `pattern` | `pattern.type`, `pattern.duplicate-alternative`, `pattern.or-binding`, `pattern.duplicate-binding` |
| `assign` | `assign.immutable`, `assign.function`, `assign.invalid-target` |
| `call` | `call.not-named`, `call.not-function`, `call.undefined`, `call.arity`, `call.print-type`, `call.argument-type` |

Where one site chooses between two templates (`'x' is a function, not a value` vs `undefined name 'x'`), it chooses the
code with the same condition. The map/set rules that `pending` defers to an instantiation site keep their
`typeref.map-*` codes: `pending` stores code and message together.

## 5. Failure matrix

For `check --format=json` and `inspect` (`I` = `inspect` only).

| Case | stdout | stderr | exit |
|---|---|---|---|
| Success | response, `ok:true`; I: `semantics.available:true` | empty | 0 |
| Lexical, syntax or import errors (any file) | response; checking does not run (as today) | empty | 1 |
| Type errors | response | empty | 1 |
| Root not well-formed UTF-8 | response, `files:[]`, one `source.invalid-utf8`: `primary` = `{file:null, path:<root>, range:[B,B+1)}` | empty | 1 |
| Root unreadable or missing | response, `files:[]`, one `io.root-unreadable`: `primary` = `{file:null, path:<root>, range:null}`; I: `reason:"io"` | empty | 2 |
| Import unreadable/missing | `import.unreadable` at the path literal; `related` = `[{role:"import-target", file:null, path:<target>, range:null}]` | empty | 1 |
| Imported file not well-formed UTF-8 | `import.invalid-utf8` at the path literal; `related` = `[{role:"import-target", file:null, path:<target>, range:[B,B+1)}]` | empty | 1 |
| Import path invalid (NUL) | `import.invalid-path` at the literal; `related:[]` | empty | 1 |
| Usage error | nothing | human usage, as today | 2 |
| Internal compiler panic | not guaranteed | not guaranteed | 101 |

Exit statuses are the existing ones. With errors, `inspect` reports `semantics:{"available":false,"reason":"diagnostics"}`.

Import cycles and diamonds are not errors (each file loads once, as today) and produce no diagnostics; they are
covered by tests so that ids and `files` order stay pinned.

## 6. v0.9b: `semantics`

```json
"semantics":{"available":true,"declarations":[ ... ]}
"semantics":{"available":false,"reason":"diagnostics"}   // or "io"
```

When unavailable there is no `declarations` key: the partially typed program is unspecified and never exposed.

### 6.1 Declarations

Every named thing in the entry point's closure:

| `kind` | From | Extra keys |
|---|---|---|
| `fn` | function declarations | `signature` |
| `param` | function parameters | `type`, `scope` |
| `local` | `let`/`var`, `for` variables, `let … else`, `if let` and `match` binders | `type`, `mutable`, `scope`, `shadows` |
| `struct` | struct declarations | — |
| `field` | struct fields | `type`, `parent` |
| `enum` | enum declarations, generic or not, and instantiations | `type_params` (generic), `of`, `args` (instantiation) |
| `variant` | enum variants (of declarations and of instantiations) | `payload`, `parent` |
| `type-param` | a generic enum's parameters | `parent` |
| `builtin-fn` | builtin functions | `signature` or `null` (variadic/special ones: `print`, `len`, …) |
| `builtin-type` | `int`, `bool`, `string`, `void`, `never`, `Map`, `Set` | — |

Common keys, in order: `id`, `kind`, `name`, `origin`, `location`, `decl_range`, then the kind's extras in the order
listed.

- `origin`: `"source"`, `"prelude"` (Option, Result, their variants and type params), `"instantiation"` (a
  monomorphised generic enum and its variants), or `"builtin"`.
- `location`: a location (§3.2) whose range is the declared **name**; `null` unless `origin` is `"source"`.
- `decl_range`: the whole declaration's range in the same file (the item for fn/struct/enum; name through type for a
  param or field; the variant's name through its payload; the statement for `let`/`var`; the binder for loop and
  pattern binders); `null` when `location` is.
- `scope`: the id of the enclosing `fn`. `shadows`: the id of the param or local this one hides (the binding the same
  name resolved to just before this declaration), or `null`. A redeclaration in the same scope is an error, so on
  success `shadows` always points to an outer scope.
- `parent`: the id of the owning struct or enum. `of`: the generic enum's id. `args`: the instantiation's type
  arguments.
- Facts are recorded by the checker at the moment it resolves each declaration; nothing is read back from the typed
  dump or re-derived from source.

### 6.2 Types

```
{"kind":"int"} {"kind":"bool"} {"kind":"string"} {"kind":"void"} {"kind":"never"}
{"kind":"array","element":T}
{"kind":"map","key":T,"value":T}
{"kind":"set","element":T}
{"kind":"struct","name":"Point","decl":3}
{"kind":"enum","name":"Option[int]","decl":41,"args":[T...]}   // decl = the instantiation's id; args omitted when not generic
{"kind":"param","name":"T"}                                     // only inside a generic enum's own variants
```

`signature` = `{"params":[{"name":"x","type":T,"decl":12}],"ret":T}`; builtin params have `"decl":null`.
`payload` = `[T...]`. `name` is the display spelling, for humans; consumers use `decl`.

### 6.3 Ids and order

After checking, facts are stably ordered: source declarations by global span start (load order, then position;
a declaration before its children), then prelude, then instantiations in first-use order, then builtins by name. A
fact's `id` is its index in that order; `scope`, `shadows`, `parent`, `of` and `decl` are remapped to ids.

## 7. Implementation

- **Codes.** `Diag` and `LexError` gain `code: string`. `report`, `say`, `add_error`, `error_at`/`fail`/`expect` and
  `import_error` take a code. `Env.pending` stores code + message.
- **Front end once.** `asterc.aster:main` is split: a `front_end(path)` returns the files, the diagnostics (including
  the root I/O and UTF-8 cases as `Diag`-like records carrying a path and no file), the checked program when there is
  one, and the exit status. The human reporter (unchanged text) and the JSON reporter both render from it.
- **New modules.** `json.aster` (escaping and string building, no parser). `inspect.aster` (global → file-local
  ranges using `SourceFile.base`/`bom`, the envelope, the declarations and type encoders).
- **Facts as a side table.** `Env` gains `decls`, appended at registration and in `declare`/`declare_existing`.
  `Local`, the typed tree, lowering and the IR do not change, so the typed dump and emitted C are untouched.
- **Prelude** declarations come from a separate parse whose spans would collide with root offsets: they are recorded
  with `origin:"prelude"` and no location, never with their parse spans.
- No new language features or builtins are used in `asterc-self`, so the two-step rule does not require a release
  between v0.9a and v0.9b.

## 8. Testing

All new suites are stage-aware (`tests/stage.ts`): S1 under `pnpm test`, and every stage including SL1 under
`pnpm selfhost`, against the same snapshots, so JSON is byte-identical across stages.

- `tests/json_check.test.ts` (v0.9a): fixtures for astral text before a span, BOM, CRLF, no final newline, a
  zero-width diagnostic (`main.missing`), malformed UTF-8 in the root and in an import, a missing root, a missing
  import, an unreadable import (skipped when running as root), import cycles and diamonds, and an error in an imported
  file. Snapshots in `tests/golden/json/`. Every matrix row asserts stdout, empty stderr and the exit status. Every
  case runs twice and compares bytes. Usage errors for `--format`.
- `tests/diag_codes.test.ts`: producer code literals equal the README catalogue.
- `tests/json_inspect.test.ts` (v0.9b): shadowing (a param hidden by a local, nested blocks, match binders),
  generic instantiations (`Option[int]`, a user generic), prelude and builtin entries with null locations,
  `available:false` on the failure fixtures.
- `tests/inspect_consumer.test.ts`: the acceptance consumer, using only `JSON.parse` on stdout. A broken multi-file
  program: it finds the diagnostic by `code`, slices the file's bytes at `range` and gets the offending token. The fixed
  program: it finds a function by name, checks its signature types, and slices its name range to the name.
- Existing human goldens, runtime/backend parity and the fixed-point proof keep passing. The only intended snapshot
  change is the usage text; any other compiler-source summary change is justified individually in the PR.
