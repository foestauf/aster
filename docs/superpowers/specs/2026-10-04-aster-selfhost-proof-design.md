# Aster Self-Hosting Proof: Stages 1 to 3 (Design)

**Date:** 2026-10-04
**Status:** Approved in brainstorming
**Issue:** #20. It also resolves #12 and #13.
**Baseline:** `f0e8dce` (the driver, PR #29).
**Builds on:** [`2026-10-04-aster-self-hosting-contract-design.md`](2026-10-04-aster-self-hosting-contract-design.md)
(cited as "contract §n").

## 1. Purpose

#19 gave us S1 and showed that S1 builds S2. #20 is the proof gate. It does four things:

- builds S1, S2 and S3 from one commit,
- runs the conformance suite (contract §6) against each stage,
- confirms that the C produced at every hop is the same,
- packages all of that into one command that can be re-run and that fails loudly on drift.

It also closes two open correctness questions in stage 0, #12 and #13. Those must be settled before the proof can be
declared (contract §7).

Decisions taken in brainstorming:

1. The proof is a Node orchestration script, `pnpm selfhost`. It runs the existing vitest suites once per stage, with
   the stage chosen by an environment variable. A plain `pnpm test` stays as it is now: S0 plus S1.
2. #13 is fixed in stage 0. An invalid escape consumes the whole following code point, as `lexer.aster` already does.
3. #12 is reproduced on disk and fixed in stage 0: the root is keyed by its physical path. The self-hosted loader keeps
   lexical identity (contract §7).
4. Evidence: each run writes a gitignored `.selfhost/` report. `docs/self-host/proof.md` is a committed record,
   generated by `pnpm selfhost --record` from a clean tree.

## 2. #13: invalid escape before an astral character

**Today.** In a string literal, `packages/asterc/src/lexer/lexer.ts` handles an invalid escape by consuming a backslash
plus one UTF-16 unit. For `"\😀"`, the diagnostic therefore quotes `\` followed by a lone high surrogate. The string's
value then keeps a lone low surrogate, and the span is `[i, i+2)`. `lexer.aster` instead consumes the backslash plus the
whole UTF-8 character.

**Fix.** The width becomes `1 + (the length of the code point at i+1 in UTF-16 units)`. That is 1 at EOF or a newline,
as today. It is 3 for an astral code point and 2 otherwise. The message, span and cursor all use this one width, so no
surrogate is ever split.

Character literals already reject `'\😀'` as "must be a single ASCII character" over the whole literal. A fixture pins
that and shows it is unaffected.

**Coverage.**

- The first commit adds the fixtures and the expected outputs. It records the mismatch as it stands before the fix
  (taken from S0's in-process output) in the commit message.
- New fixture: `tests/programs/programs/fixtures/lex_escape_astral.txt`. It covers astral and BMP characters after a
  backslash, with a following token, at EOF, before a newline, and with valid escapes alongside. It joins the lex and
  parse parity corpora automatically, because they glob `fixtures/lex_*.txt`.
- Lexer unit tests in `packages/asterc/src/lexer/lexer.test.ts` check the message, the span and the decoded value.
- A new compile-error golden, `tests/programs/errors/invalid_escape_astral.aster`, covers the checker and CLI path.
  Through `asterc_self.test.ts` it also compares the S0 and S1 renderings, including the UTF-16 caret width.
- `docs/self-host/friction.md` entry 9 is updated with the verified result.

## 3. #12: root identity through a symlinked directory

**Today.** `loadProgram` seeds its `loaded` set with `host.realPath(resolve(root.path))`. `resolve` folds `link/..`
lexically before any symlink is followed, so a root spelled `entry/link/../root.aster` gets keyed as
`entry/root.aster`. An import that reaches the real file `other/root.aster` doesn't match that key, so the root loads a
second time. Node's `realpathSync` also normalises lexically first, while `realpathSync.native` does not.

**Fix.**

- `nodeLoadHost.realPath` uses `realpathSync.native`.
- The root is keyed by `host.realPath(root.path)`, with no `resolve` first.
- Display paths (`SourceFile.path`) are unchanged.
- Imports keep their current rule: they are joined lexically in the importer's directory string, then realpath'd. The
  first step needs checking. If an import is joined to the importer's spelled directory with `join`, then
  `link/../x` would be folded before the symlink is followed. The plan checks this, and if it is wrong, applies the same
  native, no-fold treatment to imports, in the same commit.

**Coverage.** A new vitest file, `tests/load_symlink.test.ts`, builds an on-disk tree in a temp dir:

- `entry/link` is a symlink to `other/dir`.
- `other/root.aster` imports `helper.aster`.
- `helper.aster` imports `root.aster` by its physical path.

The test then runs S0 `check` and `build --emit=c` on the root under both spellings, aliased and canonical. Before the
fix, the aliased spelling reproduces the double load: a duplicate `main` or duplicate declarations. After the fix, both
spellings load two files, the cycle terminates and no diagnostic appears.

The existing in-memory `LoadHost` tests stay as they are, and one is added for the mock case. The suite also records,
through one S1 test, that S1 still uses lexical identity on the aliased spelling. That is the documented limit in
contract §4.5 and §7, asserted rather than hidden. If the test environment can't create symlinks, the test fails with a
clear message. It doesn't skip, because the platform in contract §2 supports symlinks.

## 4. Stage-aware suites

A new module, `tests/stage.ts`, is the single source of the compiler under test:

```ts
export interface Stage { name: 'S1' | 'S2' | 'S3'; bin: string }
export function stage(): Stage   // ASTER_STAGE_BIN + ASTER_STAGE if set; else S1, built once from S0 into a temp dir
export function buildWithStage(src: string, out: string): void   // `<bin> build <src> -o <out>`, throws on failure
```

If `ASTER_STAGE_BIN` is unset, the behaviour is exactly what `pnpm test` does today: S1 is built in process by S0 with
`-Werror`. If it is set, the binary is used as it is, and `ASTER_STAGE` labels it. The two variables must be set
together.

The following suites use `stage()`:

| Suite | Today | Change |
|---|---|---|
| `asterc_self.test.ts` | builds S1 | uses `stage()`; every comparison against S0 is unchanged. The "S2" block becomes "the next stage": the stage builds S(n+1), and S(n+1)'s `--emit=c` matches S0. |
| `selfhost_golden.test.ts` (new) | n/a | contract §6.3. Every runnable golden goes through `Sn run <file> -- <expect-args>` with `expect-stdin`, from the program's own directory, as in `golden.test.ts`. stdout, stderr and the exit code must meet the directives unchanged. |
| `lex/parse/check_aster.test.ts` | build their driver with S0 in process | When `ASTER_STAGE_BIN` is set, they build the driver with `buildWithStage`. Otherwise they keep S0, unchanged. The corpora and expectations are untouched. |
| `typed/ir/emit_aster.test.ts` | same | same change |

Under `pnpm test`, `selfhost_golden.test.ts` runs against S1. That is an added test (contract §6.1): it is the §6.3
golden run, which was missing until now. No existing expectation, corpus or directive changes. There is no skip list.

## 5. `pnpm selfhost`

`scripts/selfhost.ts` runs under Node with `--experimental-strip-types`, like `gen-runtime.ts`. It only orchestrates
(contract §6.4): it spawns `pnpm`, the stage binaries, `cc`, `git` and vitest. It never imports anything from
`packages/asterc`. A test enforces that by reading the script's import lines.

**Steps.** The script stops at the first failure and prints which step failed.

1. **Environment.** It records `git rev-parse HEAD` and whether the tree is dirty, along with `uname -sm`,
   `cc --version` (first line), `node --version` and `LC_ALL=C`. It fails unless the platform is Linux x86_64 with
   gcc 13 and Node 24 or later (contract §2).
2. **S0.** It runs `pnpm build`.
3. **Stages**, in a fresh `mkdtemp` directory, with the cwd at the repo root and the root spelled
   `packages/asterc-self/asterc.aster`:
   - `S0 build --emit=c` gives `c0.c`, and `S0 build -o s1` gives S1.
   - For n = 1, 2, 3: `Sn build --emit=c` gives `cn.c`, and `Sn build -o s(n+1)` gives the next stage.
   - S4 is built only to show that S3 can compile the compiler again without the TypeScript front end. Its
     `--emit=c` (`c4.c`) is compared too.
4. **C oracle.** It requires `c0 = c1 = c2 = c3 = c4` byte for byte, with no normalisation. On drift it prints the first
   differing line number and both lines, and fails. Since `c1` is the C that built S2 and `c2` is the C that built S3,
   this check covers that requirement too.
5. **Suites.**
   - Once with `pnpm test` (the S0 baseline plus S1).
   - Then once per stage for S1, S2 and S3: `vitest run` on the stage-aware suites from §4, with `ASTER_STAGE_BIN` and
     `ASTER_STAGE` set and `--reporter=json --outputFile=.selfhost/<stage>.json`. Pass, fail and skip counts come from
     the JSON.
   - Any failure, or any skipped test, fails the proof.
6. **Report.**
   - It prints a header (commit, cc, uname, node) and a table: one row per stage, with columns for the C sha256,
     whether it matches C(S0), and the suite counts.
   - It writes `.selfhost/report.txt`, `.selfhost/report.json` and the five `.c` files. `.selfhost/` is gitignored.
   - It exits 0 only if everything passed.

`--record` also writes `docs/self-host/proof.md` from the report, and refuses to run on a dirty tree. The committed
record pins the revision it was generated from, so it is always one commit behind the commit that adds it. The record
says so.

## 7. Non-goals

- Making the self-hosted compiler the default build path. That is #21.
- Malformed UTF-8 (#25).
- Symlink support in the self-hosted loader.
- CI wiring.
- Binary equality between stages.
- Performance work. The baseline is about 3 s and 239 MB peak RSS per stage build.

## 8. Testing summary

- `pnpm build && pnpm test && pnpm lint && pnpm typecheck` pass.
- `pnpm selfhost` passes and prints the table.
- `pnpm selfhost --record` produces `docs/self-host/proof.md` on the final commit's parent.
- Drift detection is unit-tested, not simulated. The byte comparison and its first-difference report live in an exported
  function, `firstDifference(a, b)`, in `scripts/selfhost.ts`; the script only runs `main` when executed directly.
  `tests/selfhost_script.test.ts` tests that function on equal input, a differing line, a trailing newline and a length
  difference. The same file also asserts that the script imports nothing from `packages/`.
