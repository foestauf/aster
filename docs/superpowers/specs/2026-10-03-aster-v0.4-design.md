# Aster v0.4: Literal Patterns, Character Literals, stderr and exit (Design)

**Date:** 2026-10-03
**Status:** Approved in brainstorming
**Builds on:** [`2026-10-02-aster-v0.3-design.md`](2026-10-02-aster-v0.3-design.md) and [`2026-10-03-aster-parse-aster-design.md`](2026-10-03-aster-parse-aster-design.md). Everything in v0–v0.3 still holds unless this document changes it.

## 1. Purpose

Writing `lex.aster` and `parse.aster` produced a ranked friction log ([`docs/self-host/friction.md`](../../self-host/friction.md)). Its two big items, error propagation (with generic enums) and modules, are separate milestones. v0.4 takes the cheap items off the list:

| Shortlist item | Friction entries | v0.4 feature |
|----------------|------------------|--------------|
| 4. stderr and exit codes | 4 | `eprint` and `exit` builtins |
| 5. `match` on string and int values | 5, 8 | literal patterns and or-patterns |
| 6. Character literals | 6 | `'a'` as an `int` |

Every feature is dogfooded. `lex.aster` and `parse.aster` learn the new syntax, so the conformance suites keep parity over the whole corpus, and their internals are rewritten to use it.

### Success criteria

v0.4 is done when:

1. The golden suite covers every feature in §3, including every new compile error.
2. `lex.aster` and `parse.aster` lex and parse all v0.4 syntax, and `tests/lex_aster.test.ts` and `tests/parse_aster.test.ts` pass over the whole corpus, including the new golden programs and new fixtures.
3. `lex.aster` and `parse.aster` use the new features where they fit (§5):
   - byte comparisons against magic numbers become character literals
   - `if k == "…"` dispatch chains on token kinds and keyword tables become `match` on strings
   - `level_ops` and other int `if` chains become `match` on ints
   - diagnostics go to stderr through `eprint`, and usage and read failures use `exit`
4. `docs/spec/language.md`, `README.md` and `docs/self-host/friction.md` describe v0.4. The friction log marks entries 4, 5 and 6 (and the `match` on ints part of 8) as resolved.

### Non-goals for v0.4

Range patterns (`'0'..='9'`), binding inside or-patterns, nested patterns, match guards, `match` on structs or arrays, multi-byte or Unicode character literals, `print` without a newline, writing files, generics, `Result`/`?`, and modules.

## 2. Semantics decisions (summary)

- **A character literal is an `int`.** `'a'` is `97`. There is no `char` type. The literal holds one ASCII byte or one escape.
- **Strings and characters share one escape set:** `\n \t \r \\ \" \' \0`. Strings gain `\r` and `\'`, which were compile errors before, so no valid program changes meaning.
- **`match` accepts `int`, `bool` and `string` scrutinees** as well as enums. Patterns can be literals, and any non-`_` pattern can be an or-pattern `a | b | c`.
- **Int and string matches need `_`.** Bool matches are exhaustive with `true` and `false`, and enum matches with every variant, as now.
- **Or-pattern alternatives cannot bind names.** `E::A(_) | E::B` is fine, and `E::A(x) | E::B` is an error.
- **`eprint` is `print` to stderr.** **`exit(code)` ends the process** and ends a control path like `panic`.

## 3. Language changes

### 3.1 Lexical

**Character literals.** A new token kind, `char`. It starts with `'` and its body is exactly one of:
- a printable ASCII byte (0x20–0x7E) other than `'` and `\`, or
- an escape from `\n \t \r \\ \" \' \0`.

Its value is the byte's value: `' '` is 32, `'\n'` is 10 and `'\''` is 39. The token's text is its source text, quotes included.

Lexing is greedy and recovers at the closing quote or the end of the line:
- After `'`, the lexer reads up to the next unescaped `'` on the same line. If none is found, the error is `unterminated character literal`, spanning `'` to the end of the line (the newline itself is not consumed). The token is still produced, with value 0.
- `''` is `empty character literal`, spanning both quotes.
- An invalid escape is `invalid escape sequence '\q'`, with the same span and wording as in strings.
- A body of two or more units, or a non-ASCII or control character, is `character literal must be a single ASCII character`, spanning the whole literal.
- One literal reports at most one error. Every erroneous literal still produces a `char` token with value 0, so the parser doesn't cascade.

**Escapes.** `ESCAPES` gains `r` (carriage return) and `'` (apostrophe) for both strings and characters.

**Punctuation.** `|` is a new single-character punctuator. `||` is still one token, because two-character punctuators are tried first.

**Keywords.** None are added. `eprint` and `exit` are builtin names.

### 3.2 Grammar

```
pattern     = "_" | alternative { "|" alternative } ;
alternative = literal | IDENT "::" IDENT [ "(" binder { "," binder } ")" ] ;
literal     = [ "-" ] INT | CHAR | STRING | "true" | "false" ;
primary     = INT | CHAR | STRING | "true" | "false" | IDENT | … ;     (CHAR added)
```

- `_` is only allowed as a whole pattern. `_ | 1` fails with `expected '=>', found '|'`, and `1 | _` with `expected pattern, found '_'`.
- `-` in a pattern negates only an INT. An int literal pattern is range-checked like an int expression, and `-9223372036854775808` is accepted. Out of range is `integer literal out of range`, recorded without failing, as for expressions.
- A token that can't start an alternative is `expected pattern, found <token>`.

### 3.3 Match semantics and type rules

**Scrutinee.** `match` accepts an enum, `int`, `bool` or `string` scrutinee. Anything else is still `cannot match on 'T' values`, and an error-typed scrutinee skips pattern checking as now.

**Pattern types.** Each alternative must fit the scrutinee:
| Alternative | Fits |
|-------------|------|
| int or char literal | `int` |
| `true` / `false` | `bool` |
| string literal | `string` |
| `E::V…` | enum `E` (existing rules: unknown enum, unknown variant, arity) |

A mismatch is `pattern type 'T' does not match 'S'`, where `T` is the alternative's type (`int`, `bool`, `string` or the enum's name) and `S` is the scrutinee's type. It is reported on the alternative's span. A mismatched alternative counts as unresolved, which switches off the exhaustiveness check, as an unresolved variant does today.

**Or-patterns.**
- The arm runs when any alternative matches.
- A variant alternative in an or-pattern of two or more alternatives may only use `_` binders. A named binder is `or-pattern alternatives cannot bind names`, reported on the binder.
- A single-alternative pattern binds exactly as in v0.3.

**Reachability.** The checker keeps the set of covered values (enum tags, ints, bools or strings):
- An alternative whose value is already covered, by an earlier arm or earlier in the same or-pattern, is `unreachable match arm` when *every* alternative of its arm is covered. Otherwise, a covered alternative is `duplicate pattern alternative`, reported on that alternative.
- `_` after a `_` arm is unreachable, as is any arm after `_`, both as now.
- `_` is unreachable once the covered set is complete. Only bool and enum sets can be complete.

**Exhaustiveness.**
- An enum match must cover every variant or have `_`, and the message is unchanged.
- A bool match must cover `true` and `false` or have `_`. Otherwise it's `non-exhaustive match: missing 'true'` / `missing 'false'`.
- An int or string match must have `_`. Otherwise it's `non-exhaustive match: add a '_' arm`.

**Evaluation.** The scrutinee is evaluated once. Arms are tried in order, and strings compare by bytes, as `==` does. `match` expressions keep their rule that all arms share one non-`void` type.

### 3.4 Builtins

| Builtin | Signature | Behaviour |
|---------|-----------|-----------|
| `eprint` | `(x: int \| bool \| string): void` | Flushes stdout, then writes `x` and a newline to stderr. It is typed exactly like `print`, including the `print`-style rejection of other types. |
| `exit` | `(code: int): void` | Flushes stdout and exits the process with `code`, truncated by the OS as a `main` return value is. |

- `eprint` and `exit` join the builtin namespace, so functions, structs and enums can't use those names.
- An expression statement that calls `exit` ends its control path, as `panic` does. This affects the missing-return check, and a `match` statement whose arms all end in `exit` ends its path too.

### 3.5 Example

```aster
fn classify(c: int): string {
    return match c {
        ' ' | '\t' | '\r' | '\n' => "space",
        '"' => "quote",
        '\'' => "apostrophe",
        _ => if c >= '0' && c <= '9' { "digit" } else { "other" },
    };
}

fn precedence(op: string): int {
    return match op {
        "||" => 1,
        "&&" => 2,
        "==" | "!=" => 3,
        "<" | "<=" | ">" | ">=" => 4,
        "+" | "-" => 5,
        "*" | "/" | "%" => 6,
        _ => 0,
    };
}

fn main(args: [string]): int {
    if len(args) != 1 {
        eprint("usage: classify <text>");
        exit(2);
    }
    let text: string = args[0];
    for i in 0..len(text) {
        print(classify(byte_at(text, i)));
    }
    print(precedence("<="));
    return 0;
}
```

## 4. Compiler changes

### 4.1 Lexer and tokens

`TokenKind` gains `'char'` and `'|'`. A `char` token sets `intValue` to the byte value (0 on error). The lexer changes are as described in §3.1. The parser's token describer gives `character literal` for `char` tokens, in the same style as its other kinds.

### 4.2 AST and parser

- `Expr` gains `CharExpr { kind: 'char'; value: bigint; raw: string; span }`.
- `Pattern` becomes:
  ```ts
  type Pattern =
    | { kind: 'wildcard'; span }
    | { kind: 'or'; alternatives: Alternative[]; span }   // two or more
    | Alternative;
  type Alternative =
    | { kind: 'variant'; … as v0.3 }
    | { kind: 'intPat'; value: bigint; raw: string; span }   // INT or "-" INT; raw is the source text
    | { kind: 'charPat'; value: bigint; raw: string; span }
    | { kind: 'stringPat'; value: string; raw: string; span }
    | { kind: 'boolPat'; value: boolean; span };
  ```
  A single alternative is stored bare, without an `or` wrapper.
- `parsePattern` parses `_` or a `|`-separated list. `sexpr.ts`'s `patternText` renders literals by their source text and or-patterns as `(| a b c)`.

### 4.3 Checker

- `checkMatch` generalises over four scrutinee categories (enum, int, bool and string), with one covered-set per match. §3.3 sets out the rules.
- `TPattern` becomes:
  ```ts
  type TPattern =
    | { kind: 'wildcard' }
    | { kind: 'variants'; variants: { name: string; tag: number }[]; binders: (Local | null)[] }  // binders only for a single variant
    | { kind: 'ints'; values: bigint[] }      // int and char literals; bools as 0n / 1n
    | { kind: 'strings'; values: string[] };
  ```
  An alternative that fails to resolve contributes no value. An arm left with no values is typed as an empty `ints`/`variants` list and is never reached.
- `checkMatchExpr` drops its `scrutinee.type.kind !== 'enum'` guard and accepts any of the four categories.
- `eprint` is a special builtin typed like `print`. `exit` goes in `BUILTIN_SIGNATURES` as `(int): void`. The divergence check (`expr.builtin === 'panic'`) also accepts `exit`.

### 4.4 IR and lowering

- The `switch` terminator's case value widens from `number` to `bigint`. Enum lowering passes `BigInt(tag)`.
- `lowerMatch` dispatches on the scrutinee's category:
  - **enum**: as now, plus every variant of a `variants` pattern becomes a case that targets the arm.
  - **int and bool**: `switch` directly on the scrutinee value. Each value of an `ints` pattern is a case, and the `_` arm (or `null`, when a bool match is complete) is the default.
  - **string**: a chain in arm order. For each value, a temp `t = str_eq s, "lit"`, then `br t armN next`. The chain ends by jumping to the `_` arm, which the checker guarantees is there.
- `IrBuiltin` gains `eprint_int`, `eprint_bool`, `eprint_string` and `exit`. `irBuiltin` maps `eprint` by argument type, as it does for `print`.

### 4.5 C backend and runtime

- `switch` case values are emitted with the same int-literal formatting as operands (`INT64_C(n)`, `INT64_MIN`). A `bool` scrutinee switches on its `0`/`1` value.
- The runtime adds `aster_rt_eprint_int/bool/string`, which `fflush(stdout)` and then write to stderr, and `_Noreturn void aster_rt_exit(int64_t code)`, which does `fflush(stdout); exit((int)code);`.

### 4.6 Unchanged

Name resolution, structs, arrays, the CLI and the driver.

## 5. Self-hosted lexer and parser

Both files keep the line formats from the v0.3 spec (§5.2) and the parse.aster spec (§3), with these additions and one change.

**Lexer format.** `char` tokens print as `char S E 'x'`, using the source text. `|` prints as `| S E |`.

**Tree format.** These rows are added:

| Node | Line | Children |
|------|------|----------|
| char | `char S E raw` | — (`raw` is the source text, quotes included) |
| or-pattern | `or-pattern S E` | alternatives |
| int pattern | `int-pattern S E raw` | — (`raw` includes a leading `-`, e.g. `-5`) |
| char pattern | `char-pattern S E raw` | — |
| string pattern | `string-pattern S E raw` | — |
| bool pattern | `bool-pattern S E true` | — |

**Diagnostics move to stderr.** Both programs print `error S E message` lines with `eprint` and exit through `exit(1)` when any were reported. Usage and read errors use `eprint` and `exit(2)`. Stdout holds only tokens or the tree. The conformance tests compare stdout and stderr separately, the fixture golden tests gain `expect-stderr` lines, and the order of the error lines doesn't change.

**Rewrites.** Each rewrite has to keep the conformance suites green:
- `is_digit`, `is_ident_start`, whitespace and escape tests, the BOM check and other byte comparisons use character literals. Or-patterns appear where a value set is enumerated (whitespace, escape letters).
- `is_keyword`, the punctuator tables, `parse_statement`/`parse_primary`/`describe` dispatch, `let`/`var` and `break`/`continue` and `true`/`false` pairs, and the keyword-to-kind mapping become `match` on strings.
- `level_ops(level)` and any other int `if` chains become `match` on ints.
- Where a rewrite would make the code longer or less clear, the `if` stays, and the reason is noted in the friction log.

The duplicated lexer at the top of `parse.aster` is updated in step with `lex.aster`. Modules remain a later milestone.

## 6. Testing

### 6.1 Golden programs

A new `literals/` folder:
- character literals: every escape, printable edge cases (`' '`, `'~'`), arithmetic on chars, comparing `byte_at` to a char
- string escapes `\r` and `\'`

Additions to `match/`:
- int match with or-patterns, negative literals, `INT64_MIN`, char literal patterns on an int scrutinee
- string match with or-patterns, the empty string, strings that share a prefix
- bool match: exhaustive without `_`, and with `_`
- enum or-patterns with `_` binders
- match expressions and statements in each category, a scrutinee evaluated once (int and string), and every arm ending in `exit` in a non-`void` function

A new `io/` program set: `eprint` of each type, interleaved with `print` (`expect-stdout` and `expect-stderr`); `exit(0)`, `exit(3)` from a nested call, and `exit` after `print` flushing stdout.

Additions to `errors/`:
- lexical: unterminated, empty, multi-character and non-ASCII character literals, and an invalid char escape
- parse: `_ | 1`, `1 | _`, `expected pattern`, `-'a'` in a pattern, and an out-of-range int pattern
- type: each pattern/scrutinee mismatch pair, a named binder in an or-pattern, `duplicate pattern alternative`, `unreachable match arm` for a literal (a repeat, and a full or-pattern repeat), `_` after `true | false`, both `non-exhaustive` forms for bool and `add a '_' arm` for int and string, `match` on a struct or an array (unchanged message), `eprint` of an enum or an array, `exit("x")`, `exit()`, and a function named `eprint` or `exit`
- missing return: a function ending in `exit(1);` is accepted

### 6.2 Self-hosted fixtures

New `fixtures/lex_chars.txt` (every char-literal form and error, plus `|`) and `fixtures/parse_patterns.txt` (every pattern form and parse error). Both conformance tests pick them up from the existing fixture glob.

### 6.3 Unit tests

The lexer, parser, checker, lowering and emit tests follow the existing per-module pattern: tokens for chars and `|`, the AST for patterns, typed patterns and diagnostics, IR for each match category, and C for `switch` with `INT64_C` cases and the string chain.

### 6.4 Workflow

As in v0.3: TDD per feature, golden tests first, then unit tests where a golden test can't reach. Implementation order: lexer, then parser, checker, IR and C, and builtins. Each stage commits with its tests. The self-hosted updates come last, in two steps: parity (new syntax) first, then the dogfooding rewrites, each keeping the suites green.

## 7. Looking ahead (informing, not in scope)

- **v0.5, error handling:** generic enums (`Option[T]`, `Result[T, E]`) and `?`. Removes `failed` and the `bad_*` placeholders from `parse.aster`.
- **v0.6, modules:** removes the duplicated lexer and unblocks a self-hosted checker.
- Range patterns and binding or-patterns may return if the self-hosted checker wants them.
